Privacy Policy

This policy details the exact information processed, stored, and managed by DAMU Server Builder based on an audit of its source code.

Application: DAMU Server Builder
Repository: krishnverma32/damu-server-builder
Last Updated: September 24, 2026

1 Overview & Privacy Commitment

DAMU Server Builder ("the Bot", "we", "our") values the privacy of Discord communities and individual users. We adhere to the principle of data minimization: we only collect and process data necessary to provide server creation, ticket management, moderation, verification, leveling, and AI assistance features.

This Privacy Policy explains what Discord data we access, how it is processed in code, where it is stored, how long it is retained, and how you can exercise your data rights.

2 Information We Process From Discord

When the Bot is added to a Discord server and commands are invoked, the application accesses specific Discord API objects:

Data Element How It Is Used in Code Storage Mechanism
Discord User ID & Username Associates moderation warnings, ticket ownership, blacklist status, XP progression, and AI chat memory. Stored in MongoDB (ticket configs/blacklist) & local JSON files (XP, warnings, AI memory).
Guild / Server IDs Identifies the server for configuration settings, analytics tracking, automod settings, and server-building schemas. Stored in MongoDB (ticket guild configs) and local JSON files (analytics, automod, verification).
Channel & Role IDs Configures log channels, welcome channels, ticket categories, verification roles, and autoroles. Stored in MongoDB and local server configuration JSON files.
Server Structure & Metadata Used during /server_build or /server_inspect to analyze and create channels, voice rooms, categories, and permission overwrites. Processed in-memory; last applied schema optionally saved to local preview file for comparison.

3 Message Content & Interaction Processing

The Bot operates with the message_content Discord intent enabled for specific, clearly defined functional operations:

  • Server Analytics (cogs/analytics.py): The Bot increments a numeric counter of messages sent per day per server. Raw message content is NOT stored, logged, or recorded for analytics.
  • Leveling & XP (cogs/leveling.py, services/level_service.py): The Bot increments user message counts and awards XP on active chat channels. Message text is NOT stored.
  • AutoMod & Link/Spam Detection (cogs/automod.py): Messages are evaluated in real-time for unauthorized invite links or rapid image flooding. When an offense occurs, the user ID and offense count are stored. Message content is NOT saved after evaluation.
  • AI Chat Assistant (cogs/ai.py, services/ai_service.py): When a user invokes /ai <prompt>, the prompt and assistant response are held in memory for up to 10 conversation turns to provide conversational context. Users can immediately erase this history at any time using /ai_reset.
  • Support Ticket Transcripts (cogs/ticket_system.py, services/ticket_service.py): When a ticket is closed, a transcript containing recent message history (timestamps, authors, text) from that specific ticket channel may be generated and delivered to the server's configured ticket log channel or transcript channel.

4 Data Storage & Database Architecture

The application employs two storage layers depending on hosting configuration:

  • MongoDB Atlas: When MONGO_URI is configured, the ticket system uses MongoDB Atlas (via the motor async driver) to store guild ticket settings (category ID, support role ID, ticket counter, blacklisted user IDs).
  • Local JSON Storage: The application uses structured JSON files inside the data/ directory for ephemeral and server settings:
    • data/dashboard_config.json — Welcome messages, auto-roles, and command channels
    • data/verification_config.json — Verification channel, role ID, and embed settings
    • data/automod/offenses.json — Automod settings and user offense records
    • data/levels/xp_data.json — User XP and levels
    • data/warnings.json — Moderator-issued warnings with timestamps and reasons
    • data/memory/user_memory.json — Per-user AI conversation context (max 10 exchanges)
Note: On ephemeral cloud hosting (such as Render instances without persistent disks), local data files reset across container redeployments, whereas MongoDB persists server settings.

5 Third-Party Service Providers

To deliver specific features, data is transmitted to trusted third-party providers:

  • Discord API: Delivers all messages, command responses, and guild interactions under Discord's Privacy Policy.
  • OpenRouter: When /ai is used, prompts and context history are securely transmitted via HTTPS to OpenRouter (OpenRouter Privacy Policy) to generate responses using selected models (e.g., NVIDIA Nemotron, Gemma, Arcee MoE).
  • GIPHY API: If enabled for welcome embeds, queries (e.g., "welcome discord") are sent to GIPHY to retrieve animated GIF URLs. No personal user data is sent.
  • MongoDB Atlas: Hosts persistent guild configurations for the ticket management module.
  • Render: Cloud container hosting provider executing the bot runtime and keep-alive health server.

6 Data Retention & Automated Deletion

We enforce explicit retention limits and automated cleanup:

  • AutoMod Offenses: Offense counters automatically expire and reset after 24 hours.
  • Closed Tickets: Closed ticket channels are automatically deleted after a 10-second grace period.
  • AI Memory: Retains a sliding window of at most 10 exchanges. Users can trigger immediate erasure at any time via /ai_reset.
  • Server Configuration: Maintained while the bot is an active member of the guild, or until cleared by administrators.

7 Security Standards

We take security seriously. All credentials (including DISCORD_TOKEN, MONGO_URI, and OPENROUTER_API_KEY) are managed exclusively through secure environment variables and are never hardcoded into source code or exposed in web responses.

The built-in Flask web server serves only health checks and these static legal documents. It never displays tokens, server IDs, or stored data.

8 User Rights & Data Deletion Requests

Users and server administrators have the right to request access to or deletion of data associated with their Discord account or server:

  • Self-Service AI Data Deletion: Run /ai_reset in any channel where the bot is present to immediately wipe your conversation context.
  • Guild Data Deletion: Removing the bot from your server halts all data processing. To request manual removal of stored guild configurations, ticket logs, or warning records from MongoDB/local storage, please open a request on our repository.
